Prefer the simplest correct implementation consistent with the existing codebase. Before adding code, prefer suitable project implementations, then standard-library or platform capabilities and existing dependencies, before writing new code. Identify affected callers, interfaces, configuration, and tests; make the smallest complete change across that scope without weakening readability, compatibility, security, or required verification, or silently reducing the requested scope. Avoid redundant comments, explanatory boilerplate, unnecessary helper layers, and unrelated refactoring. Preserve required APIs, edge cases, tests, and non-obvious invariants. Never sacrifice correctness just to reduce code length.
