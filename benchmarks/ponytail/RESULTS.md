# Ponytail 原则内化：v2 完整消融结果

## 结论与生产决策

**本轮生产默认选择 B：复用优先。** 保留原有最简单正确实现、API、边界、测试和非显然约束；不内置 Ponytail 人设、模式切换或固定回复格式。C 的跨影响链“最小完整变更”强化句保留为实验变体，不叠加到默认提示词。

- 三组均 21/21 通过；3 场校准亦全部通过。没有超时、控制审计失败或原测试/只读文件变化。
- B 相对 A：累计耗时减少 **27.40%**，输入加输出 Token 减少 **35.63%**。21 个逐对比较中 B 更快 14 个、较慢 7 个；逐对耗时比中位数下降 **4.08%**。不能把累计降幅当成典型单场加速幅度。
- C 相对 B：累计耗时增加 **3.52%**，输入加输出 Token 增加 **4.79%**；21 对中 C 更快 7 个、较慢 14 个，逐对耗时比中位数增加 **2.91%**。本轮没有测出 C 的额外功能验收收益。
- C 的工具调用更少（127 vs B 的 136）、模型请求略少（124 vs 125），未缓存输入也更少（44,409 vs 45,816）；B 并非所有指标获胜，未知代理费率下不能宣称实际账单最低。
- B 的累计优势主要来自跨文件修复和多模块任务；A 工具错误事件更多，全部真实开销保留，未删除长尾。工具错误事件不等于最终功能失败，也未逐个归因于提示词。
- 定向复用任务三组都通过，B 在该任务累计更慢（71.546s，A 58.671s，C 60.405s），不能声称已证明“更会复用”或正确性提升。
- 仅 7 类合成任务，每类每组 3 次，未进行显著性检验。这是本轮默认选择的工程依据，不是普遍最优证明。
