# Changelog

Notable changes to Kroma are tracked here. This is a curated summary, **not** proof of a published binary or npm release. For exact history, consult [commits](https://github.com/Polaris591/kroma/commits/main) and [tags](https://github.com/Polaris591/kroma/tags).

The source currently declares version `0.4.0` in `Cargo.toml`. No public npm package is documented as published. This file deliberately does not claim a release date or a production certification.

## Unreleased

### Added
- `kroma sessions prune --older-than DAYS` deletes saved conversations whose newest file is older than the cutoff. A conversation used recently always survives any cutoff, and no other file in the directory is touched.
- Opt-in server-side `web_search` for Responses profiles (`native_web_search`): the endpoint runs the search, Kroma shows it through the existing tool activity view, keeps real source URLs with the turn and reports provider-supplied search counts.
- Opt-in Anthropic server-side search (`web_search_20250305`) behind the same `native_web_search` flag, keeping provider-reported search counts through partial streams and falling back to the local web plugin when the endpoint rejects the tool.
- Public Beta CLI/TUI documentation, configuration and first-run setup.
- Shared Rust runtime for CLI, TUI and optional Desktop preview.
- Opt-in process plugin host with tool hooks, model and context backends, streaming, event delivery and lifecycle contracts.
- Official plugin sources for Web Search & Fetch, Project Memory, Subagents and Image Generation, with separate test suites and distribution preparation.
- Image generation plugin: one `image_generate` tool plus `/image`, OpenAI Images and Gemini adapters, current/previous-turn attachment and prior-output references, a private image store and an explicit project export, with offline tests.
- Project Memory v2: `provide_context` and `task_finished` host calls, host-verified user-turn anchoring for `preference`/`decision` writes, up to four `core` rules injected on every task, and review findings that require a path plus evidence and expire after 30 days.
- Subagents plugin 2.0: the tool returns before any child finishes, so the parent keeps working and keeps taking user input; a finished answer is queued and every queued answer is delivered as one untrusted report when the current turn ends. Removed: the profile set and model tiers, `complexity`, the status/wait/continue/cancel actions, the tool-response output budget and the instruction-shaped heuristic. Answers are written in full to `answer.txt`, cancellation stays a user command (`/subagents`, Alt+X), and a resume token now arrives inside the delivered answer.
- Instruction steering: text submitted during a running task, or `/steer`, is journaled as a user message and consumed before the turn can finish; `/queue` adds a follow-up and `/pending` lists both.
- Plugin tool context contracts: `requires_user_context` supplies the current user message and turn, and `requires_user_attachments` supplies current and previous user image references, so a plugin write does not depend on model-supplied arguments.
- Desktop preview: searchable sessions (Ctrl/Cmd+K), documented keyboard shortcuts and stable transcript pagination.
- Session journals, file checkpoints, recovery and context management diagnostics.
- Cross-platform CI, native npm-package staging tests and maintainer-gated release workflows.

### Changed
- A silent tool now gets ten minutes instead of five before Kroma stops waiting (`KROMA_TOOL_IDLE_SECS` still overrides it, and 0 disables the guard).
- A context summary gets three minutes per attempt with one retry, under a 400-second ceiling for the whole checkpoint, so a slow provider no longer loses the compaction.
- Error messages name what broke and what to do: a plugin that answers a different request says which plugin and points at `kroma plugins check`, an MCP server returning the wrong shape names the content type it sent, a damaged conversation journal says nothing was deleted and how to continue, a malformed tool call from an endpoint suggests a retry or a model switch, and an unusable plugin id shows the allowed characters.
- Goal plugin: the model-facing `goal_checkpoint` schema lists only `summary`, `claim` and the optional `criteria`/`checks`/`next_step`/`block_reason`/`unverified` fields, without per-field prose, shrinking the manifest's tool section from 5,266 to 2,277 bytes. `revision`, `source`, `source_ref`, `kind`, `check_ids`, `notes` and `rationale` remain accepted and validated by the host and plugin protocol; the host still rejects stale revisions and evidence it cannot match to a real execution.
- One production execution guidance replaces seven parallel prompt texts. The shipped text is byte-identical to the previous two-paragraph default (2,209 characters), so behavior and per-request cost are unchanged while only one paragraph needs maintaining; the archived arms live in `benchmarks/legacy_prompt_arms.rs`.
- DeepSeek reasoning replay and the low-cost summary effort resolve through one capability check (`uses_deepseek_tool_reasoning`) that prefers the model catalog and keeps the documented reverse-proxy name fallback.
- `kroma plugins check`/`install` on a plugin whose manifest sits at `plugin/plugin.toml` names that directory instead of reporting a missing file; the streaming model example answers the optional smoke ping that the check sends.
- Ask plugin: the prompt is 258 characters instead of 909.
- Web Search & Fetch plugin 4.4: `web_fetch` accepts `section` to return a single chapter (matched against the reported `headings`, stopping at the next same-or-higher heading, with `SECTION_NOT_FOUND` listing alternatives); search results now carry `published` when the backend reports a date, with placeholder values dropped.
- Web Search & Fetch plugin 4.3: `web_search` accepts `time_range` (day/week/year) across the nine backends that support a date filter and reports when a backend ignored it; identical searches inside five minutes are served from memory with `cached: true`; `web_fetch` returns a `headings` outline for long pages and fetches `urls` four at a time.
- Web Search & Fetch plugin 4.2: the keyless Exa public endpoint now ranks first in the default chain, so `auto` spends no search credit until the free path fails; a stored Exa key becomes the first paid fallback.
- Web Search & Fetch plugin 4.1: Exa pulls its keyless public endpoint (MCP) into both roles — a search backend (`exa_public`, first in the free chain, same index as the paid API) and the first fallback for pages the static reader cannot use, so JavaScript sites and blocked hosts are readable without any key or spend. Firecrawl remains the second, paid fallback and the only PDF converter.
- Web Search & Fetch plugin 4.0: `web_fetch` accepts `urls` (up to 10 pages, independent results), PDFs are converted through Firecrawl instead of rejected, YouTube links return their caption transcript when the page exposes one (otherwise a clear NO_CAPTIONS note), requests carry a browser header profile that reads more sites than a bare API client, and Search1API plus Valyu join the backend list (now 17).
- Web Search & Fetch plugin 3.5: Firecrawl rendering now covers pages this network cannot reach (blocked hosts, DNS failures, timeouts) in addition to JavaScript shells and 403/429, matching its role as the fallback for anything `web_fetch` cannot read. Server errors and PDFs still never spend a rendering call, private addresses are still refused locally, and each rendered page is visibly reported as `provider: "firecrawl"`.
- Web Search & Fetch plugin 3.4.1: background DNS warm-up for every vendor host at process start, so the first search of a session no longer pays the resolver cold start (measured ~6 s on one network, ~0.3 s once cached). Failures are ignored; SearXNG hosts outside the fixed list keep their own cold start.
- Web Search & Fetch plugin 3.4: SerpApi and Linkup join the backend list, `auto` now follows a quality-ordered chain (Exa, Tavily, Brave, Kagi, You.com, Serper, Perplexity, Parallel, SerpApi, SearchApi, Linkup, Bocha, Firecrawl, SearXNG, Mwmbl) and advances only after a real failure, Chinese queries start at Bocha when configured, and the new `search_chain` setting lets the owner replace that order outright. Keyless fallback is now Firecrawl → SearXNG → Mwmbl.
- Web Search & Fetch plugin 3.3: Firecrawl search and SearchApi join the backend list. Firecrawl search also runs keyless at low volume, and reuses the rendering key; SearchApi forwards Google operators such as `site:`/`inurl:`. Contracts checked against both vendors' documentation; live calls need the owner's keys (Firecrawl already stored).
- Web Search & Fetch plugin 3.2: four more search backends behind the same one-key rule — Perplexity (`/search`), Serper (Google results), Kagi (`/api/v1/search`) and Bocha/博查 (Chinese web index). Endpoints, auth headers and response shapes verified against each vendor's current documentation; live calls need the owner's keys.
- Web Search & Fetch plugin 3.1: optional Firecrawl rendering returns for pages that need JavaScript or answer 403/429. One `firecrawl_api_key` setting, no switches; results report `provider: "firecrawl"` so a paid render is visible, and server errors, timeouts and PDFs never spend a rendering call.
- Web Search & Fetch plugin 3.0: the hand-written HTTP stack (DNS pinning, CONNECT proxy tunnel, forced identity encoding) is replaced by the system fetch, so pages are decompressed and HTTP/2 and connection reuse come for free; Firecrawl extraction, the paid-fallback chain, the priority list and the private credentials file are removed, `*_api_key` are real plugin settings so `kroma plugins set` can store them, the keyless path is Mwmbl only, continuation snapshots refresh while a document is being read, and pages that yield only navigation now fail with `UNREADABLE_PAGE`.
- Context compression and cache/usage diagnostics received further correctness and regression coverage.
- Plugin architecture, child-process handling and session/task notifications were refined.
- The terminal UI gained additional rendering, interaction and transcript tests.
- The obsolete TUI layout/width preference and the ignored `KROMA_TUI_STYLE` variable were removed; A / Plain is the only interface, and saved UI settings still load.
- Hot plugging: a plugin installed, enabled or edited outside a running Kroma applies to the next message in the terminal and the desktop window — no restart, no command to remember. The check is a fingerprint of the plugin folders, their `plugin.toml` size and modification time and the settings file, not a reload per keystroke.
- Desktop draws what a plugin declares: tool labels, the activity indicator with its status line, Alt+letter shortcuts, plugin panels (static or produced by the plugin on request), declared theme slots (painting the plugin's own panel and status line) and a composer height cap.
- `PluginCatalog::ui_panels` exposes the panels an interface may offer, so a front end never has to know a plugin by name, and `tests/plugins_e2e.rs::an_unseen_plugin_needs_no_core_change` installs `tests/fixtures/plugins/timeline-note` — an id, tool, command and panel the source has never heard of — to keep it that way.

### Removed
- Every `KROMA_EXPERIMENT_*` switch left the production path: the prompt arms (`KROMA_EXPERIMENT_PROMPT_ARM`, `KROMA_EXPERIMENT_FINISH_ON_EVIDENCE`, `KROMA_EXPERIMENT_COMPLETE_FUNCTION_READ`), `KROMA_EXPERIMENT_READABLE_SHELL_RESULTS`, `KROMA_EXPERIMENT_ADAPTIVE_FINISH` and `KROMA_EXPERIMENT_SHELL_TOOL_NAME`. The Cargo-specific "tests passed, so finish" hint and the readable-shell request projection went with them, so no request sees a rewritten tool result or a Rust-only completion rule.
- Review pass on limits and over-defence. `/compact` now caps retention at half the remaining history, a summary that fails to shrink the conversation is reported instead of failing the command, and checkpoint summaries pass in any language (a length and degeneracy check replaces seven English headings).
- AGENTS.md discovery reads only the location a tool call declares (`command`, `path`, `cwd`); it no longer holds back the rest of a batch, and no longer stops a task because a rule turned up in tool output.
- File checkpoints are taken right before the first tool that can change the working tree (`shell`, `edit_file`) instead of before the first tool of every task.
- `edit_file` accepts absolute paths inside the workspace, creates a file when `old` is empty, and keeps the file mode (an executable stays executable). The TUI reads git state with `GIT_OPTIONAL_LOCKS=0`, so it cannot fight a running git command over `index.lock`.
- Desktop: attachments and exports may live on any drive the user picks; an untracked file in the workspace review shows its content instead of a refusal; plugin slash commands run without being sent to the model and their reply is displayed.
- MCP: an approved project config keeps its environment values as written and any variable expands; the project/child/host allowlists and secret filtering are gone, and the trust fingerprint no longer hashes secret-named values.
- Project Memory: the secret scanner is gone, a rule keeps the model's complete sentence with the user's quote kept as provenance, and repeated opens in one process skip the one-time schema, flag and purge work.
- Subagents plugin 3.0: the call waits for its children and returns their answers in one result with progress lines. The host-side background job table, automatic wake-up delivery, the two-turn cap, `KROMA_NO_SUBAGENT_DELIVERY`, the `/subagents` command and the Alt+X shortcut are removed.
- Web Search & Fetch plugin 4.4.1: the private-address refusals, the SearXNG private-network opt-in, the per-session DNS warm-up and the fixed provider-host table are removed; a ten-page batch no longer evicts its own first pages after two minutes, `find` with `section` is rejected instead of silently ignoring `section`, Search1API reports `week` as unsupported, a free search with a date filter starts at SearXNG, and outlines with more than 40 headings say `headings_truncated`.
### Known limitations
- The Desktop host is a separate preview, not part of the CLI npm distribution.
- npm package names remain provisional until ownership and publication are verified.
- Real provider/gateway compatibility, performance, hardware-specific UI behavior and package publication require explicit release verification.
- Kroma intentionally executes commands without per-tool approval and is not a sandbox. See [security](docs/security.md).

Before publishing a release, create a dated version section with changes verified against the release tag and update the installation/status text in both READMEs.
