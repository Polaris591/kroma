# C00-09 嵌套调用网关与上限

Kroma 没有脚本运行时，蓝图也不要求现在就引入完整 JS VM。本包交付的是**任何执行器都必须
经过的那个入口**的记账半边：深度、调用次数、结果字节、并发、整段脚本的截止时间、取消。

代码：`crates/kroma-core/src/tool/nested.rs`（`NestedLimits` / `NestedGateway` / `CallTicket`）。

五条测试：

- **深度**：`max_depth=3` 时 depth 4 报 `DepthExceeded`；
- **次数与并发分开**：同时最多 2 个在飞；总共 4 次用完后，即使全部完成也不恢复总配额；
- **结果字节**：1025 字节对 `max_result_bytes=1024` 报 `ResultTooLarge`，且**不截断**——
  截断后的工具结果在模型看来和完整结果一样，比失败更危险；失败时在飞槽位照常释放；
- **取消后**：新调用报 `Cancelled`，已经在飞的调用允许完成并保留结果（否则会隐藏可能已发生的副作用）；
- **截止时间**覆盖整段脚本，不是每次调用单独计时。

## 尚未接线

没有执行器消费它：等真正引入脚本执行（或 Rust 侧批处理 DSL）时，嵌套调用必须从这里取票，
并在同一张票上完成授权/预算/审计。现在能说的是"上限语义已定义并被测试"，不能说
"Kroma 的嵌套调用已受限"。
