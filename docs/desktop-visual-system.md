# Desktop 视觉与交互基线

## 设计方向

默认界面使用暖石墨、中性雾白与少量灰紫提示。不再把绿色同时用于品牌、主操作、选中、启用和运行。强调色是交互线索，不是给所有控件上色的理由。

这份基线落在 `desktop/src/tokens.css` 与真实组件中，不是另一套演示页面。没有引入 UI 组件库、在线字体、装饰背景或新的主题设置页；插件显式声明的配色仍然受到尊重。

### 颜色角色

| 角色 | 默认值 / 用法 |
| --- | --- |
| 主画布 | `#19191e`，长时间阅读的低饱和石墨底色 |
| 正文与主操作 | `#eeedf2`；默认主按钮使用中性色，不使用整块紫色或绿色 |
| 次级文字 | `#aaa7b4`；说明、占位文字不通过随意降低透明度来“显得高级” |
| 交互提示 | `#b8ace8`；用于焦点、当前选项、细下划线和开关，选中面使用低比例混色 |
| 运行 / 连接 | 灰蓝色 `--info`，与成功结果分开 |
| 等待 / 未保存 / 接近预算 | `--warning`；同时配文字，不仅依靠颜色 |
| 失败 / 破坏性操作 | `--danger`；停止完成使用中性文字，不与失败混为一谈 |
| 成功 / diff 新增 | 低饱和 `--success`；绿色仅保留在这些有实际语义的位置 |

画布、侧栏、输入字段、普通面板、浮层分别有表面变量。边线、浮层阴影与圆角也使用集中角色，避免每个组件自行选择灰色、绿色或不同的黑色阴影。阴影只用于层级，不用于给每个列表项做悬浮卡片。Tauri 的启动背景与 `--bg` 同步，并用单测防止两者再次脱节；只修改了配置颜色，没有改动原生运行逻辑。

`theme.ts` 计算相对亮度与对比度。插件只提供浅色背景时，前端补齐可读的默认文字、边线与原生 `color-scheme`；明确提供的文字、边线和强调色不被覆盖。强调色按钮的文字根据背景选择，避免深紫按钮仍使用深色文字。移除插件主题会恢复内置颜色和原生控件外观。

## 信息层级与交互

### 对话与输入

- 阅读区域与输入区域保持对齐，不增加机器人头像、角色装饰条或常驻功能矩阵。
- 正文与过程仍然分开；过程面板用轻边线与背景表示附属内容。
- 代码块的语言与复制动作有单独工具栏，与代码滚动区域隔开；复制的仍是精确原文。
- 发送用向上箭头，插入当前任务用回转箭头，排队与停止各有自己的含义和标签。
- 输入框聚焦使用细边线与很轻的外环，不把整个输入区染色。附件到达上限时，按钮说明给出原因。
- 空白会话显示工作区、清晰标题与三个任务起点。点击示例只填草稿并聚焦输入框，不会自动调用模型或工具。

### 模型设置

- 宽窗把配置列表与编辑区分开；窄窗回到单列，限制配置列表高度，把空间留给表单。
- “查看的配置”“当前连接”“启动默认”“未保存”是不同状态。选择卡片不会悄悄切换模型。
- 基本信息、认证、高级参数和提交操作有明确分组；API Key 有独立标签和留空 / 清除语义。
- 保存、连接和设默认仍是不同操作。连接中锁定字段，失败保留输入，撤销草稿仍恢复已保存内容。
- 不使用遮盖字段的吸底按钮栏，也不为了让按钮常驻而给整个表单制造嵌套滚动。
- 没有配置时只显示一个明确的“添加模型”操作，避免标题与空状态重复争夺主操作。

### 能力与插件

- 工具、MCP、Skills 有一致的标题、即时保存说明、搜索、数量与来源标签；批量操作不冒充逐项开关。
- 插件页默认显示第一个可用详情，不再在已有插件旁边留下大块空面板。
- 重复选择当前插件不会重置输入；切换插件可以保留尚未保存的密钥，只保存在当前页面实例内，不写 localStorage。
- 保存失败保留输入，成功清空密钥；重试清除上一轮错误，避免成功和旧错误同时展示。
- 默认开关与会话覆盖的关系就近说明；卸载与一般设置分区，并说明保留的数据范围。

### 浮层、确认与系统偏好

- 菜单、上下文、确认、差异与插件面板共享表面和阴影角色；普通图标不无条件使用强调色。
- 浮层仅有 120ms 的透明度入场，不做位移、弹跳或缩放；控件按压也不移动命中区域。
- 减少动态效果模式尊重用户偏好。系统高对比度模式提供焦点、选中轮廓与系统色开关，不仅依靠淡紫色背景。
- 已有 Escape、焦点返回、忙碌锁定、抽屉 inert 和原生 modal 行为予以保留。

## 验证
