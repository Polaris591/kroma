--- Residual risk register ---------------------------------------------------
  R1. Snapshot cost is a full workspace walk per mutating turn. Bounded by
      MAX_SNAPSHOT_FILE_BYTES=4MiB / MAX_SNAPSHOT_TOTAL_BYTES=256MiB and by
      excluding .git/target/node_modules. NOT yet measured against a large repo; the
      blueprint requires that measurement before deciding to keep this backend.
  R2. Non-UTF-8 file names are skipped by WorkspaceCap::read_dir_no_symlink, so they
      are neither tracked nor restored and are not reported in skipped_paths.
  R3. Only paths tracked by the target or the expected revision are touched on
      restore. A brand-new untracked file is deliberately left alone (test 2).
  R4. Unknown external side effects (network, databases, spawned daemons) are not and
      cannot be rolled back; only workspace file bytes and modes are.
  R5. "--undo" restores file bytes and modes, not the cwd of a running process nor
      open file handles held by other tools.
  R6. Gate 1 does not yet implement "undo of an undo" as a first-class operation; it
      is achievable by capturing a new revision after the undo, but there is no
      dedicated redo command.
  R7. A `bash` tool call that mutates workspace files still reports no `modified_file`
      and a mutating CompletionGate verification command is still not snapshotted, so
      the workspace can drift ahead of `latest_revision_id()` for those two paths.
      Tracked as an open Gate 1 finding (see V090_GATE1_REVIEW_FIX_REPORT.md).
  R8. `SnapshotStore::store_blob` writes the final blob in place (create_new + write)
      rather than temp+rename, and `ensure_private_dir` chmods an existing directory by
      path. Both are open Gate 1 findings (see V090_GATE1_REVIEW_FIX_REPORT.md).
  R9. No dedicated `RevisionRestored` WAL/audit event and no `SnapshotStore::compare`
      API yet; the restore is auditable via the appended `revision_captured` +
      `set_leaf` records.
