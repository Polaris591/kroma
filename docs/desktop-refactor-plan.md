# Kroma Desktop 前端重构方案

> 调查日期：2026-11-12（本机日期）。状态：**方案与实施记录；主界面首批已落地，整份方案尚未全部完成**。
>
> 依据：用户提供的桌面截图、当前工作树源码、现有前端测试与构建结果。调查时 HEAD 为 `d6aa128`，但前端和插件已有较多未提交修改；本文针对的是**当前工作树**，不是该提交的纯净版本。文中位置与数字是调查快照，实施前应复核相关改动。

## 后续视觉打磨（2026-11-13）

用户明确要求不再沿用青绿强调。当前默认已改为石墨画布、中性雾白主操作与少量灰紫交互提示；绿色只保留成功与 diff 新增等语义。模型设置采用分组编辑与独立配置列表，插件默认显示详情，并补齐浅色、自定义强调色、占位文字与高对比度检查。Tauri 启动底色也与前端同步。

当前规则见 [视觉与交互基线](desktop-visual-system.md)，覆盖及边界见 [设计审查记录](desktop-design-review.md)。以下 2026-11-12 的进度是历史记录，不再代表当前配色建议。

## 实施进度（2026-11-12）

已完成主界面与设置/浮层两批改造，不代表下方全部验收项已经完成：

第一批（主界面）：

- 提取 `tokens.css`，统一石墨底色、青绿强调、正文/次文字及插件主题派生颜色；设置、插件页和浮层同步使用语义颜色。
- 侧栏增加轻量品牌标记，底部入口合并；修正宽窗口收起，并将用户选择、插件默认与窗口尺寸分开处理。
- 模型与当前思考强度整合成一个面板，补齐有/无搜索框时的初始焦点、Escape 和关闭后返回焦点；修正标题栏异步监听卸载清理。
- 用户提问改为右侧轻量消息块；回答直接排版，过程和实际改动放回正文列下方，不再悬挂到插件区域。
- 输入框降低视觉重量，保留发送、插话、排队、附件和停止；“回到最新”改为跟随对话可视区域。
- MCP 不再要求审批：启用时直接加载配置；统一设置入口和会话能力开关见下方“第三批”。
- 对话位置的插件真正进入滚动区；右侧插件在空间不足时变为可开合的浮层；插件网页和原有桥接保留。
- 增加不进入生产代码的合成 Desktop Host 和浏览器检查，见 [Desktop browser checks](../desktop/tests/README.md)。

第二批（设置、插件页与所有浮层）：

- 弹窗改用浏览器原生模态 `<dialog>`，由一个小的 `modal` 行为统一处理：打开时聚焦指定控件、Tab 只在弹窗内循环、Escape 交回弹窗自己处理、关闭后焦点回到打开它的按钮。没有引入弹窗管理器或新依赖。
- 连接中、删除中、清理中的弹窗不会被 Escape 关掉，避免出现“看不见但还在进行”的操作；失败信息显示在弹窗内，输入保留。
- 修复一个新模型“保存成功但连接失败”后再试会被当成重名配置拦住的问题；重试会复用同一配置，不会产生重复条目。
- 回退确认在提交过程中保持可见；失败后弹窗和错误都在，可直接重试，成功才关闭。
- 本机数据对话框：读取可随时关闭；清理时空会话逐个尝试，部分失败会明确显示“部分未能清理”，不再静默跳过。
- 删除会话、卸载插件、删除提示的初始焦点落在安全选项；插件卸载从浏览器 `confirm()` 换成同一套应用的确认框。
- 插件页的重新加载、开关、保存/清除设置都有忙碌状态，避免重复点击。
- 设置页补齐草稿提示、字段帮助、忙碌与错误行样式；配置名称的 `pattern` 在新版浏览器里被判定为非法表达式（`v` 模式要求转义 `-`），已改为共享常量并通过浏览器校验。
- 修掉一处真实的界面问题：同一轮既有“本轮改动”又有“工作区变更”时，后者会被隐藏；现在两者都可用。

第三批（统一设置与逐项会话能力，已实现；前端与核心回归通过，桌面原生测试启动受阻）：

- 侧栏仍只保留“设置”，内部归纳模型、工具、MCP、Skills、插件五类；顶部另设当前会话设置。分类用于导航，不是整类一关全关。
- 控制对象是每个内置工具、每个 Skill、每个 MCP 服务、每个插件。全局为每项设置开启/关闭默认值；当前会话对每项独立选择开启、关闭、跟随默认。关闭某项不连带关闭同类其他项或其他类别能力。
- “全开/全关”只作为批量选中当前清单的快捷操作；搜索后仅处理匹配项，不影响隐藏项。不能取代单项开关，也不为以后新增条目设置类别级策略。
- 全局默认和会话覆盖由 Rust 持久化，不靠浏览器本地开关伪装；单项可重置为跟随默认，不改写其他项。运行中不实际更换能力，停止或完成后再操作。
- 全局插件页只保留原插件管理区，选中每个插件后只有一个默认启用开关，保留安装、配置和卸载，不另列重复的启用清单；默认关闭的插件可以只在某个会话开启，不改写默认值。
- 去重修正验证：前端检查 0 errors / 0 warnings、160 项单元测试、生产构建和逐项能力浏览器 8 组通过；包含唯一插件管理模块、插件间启停互不影响、会话三态保留、运行中默认开关禁用。桌面 `custom-protocol` release 构建通过，未自动关闭或重启用户窗口；浏览器结果来自合成宿主，不等于原生窗口实测。
- 关闭后清单仍可见，不卸载、不删除配置；关闭的插件不再贡献运行时能力或自定义界面，但不能在活动任务中实际切换。
- 取消 MCP 审批和待授权提示，启用的服务直接按配置加载；清单不暴露环境变量、请求头或密钥。
- MCP 服务定义继续读取 `~/.kroma/mcp.json`、项目 `.kroma/mcp.json` 或 `KROMA_MCP_CONFIG` 指定文件；Skills 继续读取用户/项目 `.agents/skills`、`.kroma/skills` 下的 `SKILL.md`。没有新增定义编辑器或安装市场。
- 插件显示数据保留异步顺序保护，避免旧会话的迟到回复把已关闭的插件界面重新显示。

## 一、先说结论

**保留现有功能和技术栈，重整视觉、信息层级和组件边界；不重写整个前端。**

目标是把 Kroma 从“功能都摆在外面的开发工具”，变成“安静、有温度、想法能自然接上的工作台”：

- 第一眼看见内容和输入框，而不是一排配置、指标与状态。
- 平时简洁，工作时能看清正在做什么、哪里失败、怎么停止。
- 收起的是视觉噪声，不是能力、错误、风险或用户的控制权。
- 有自己的字体节奏、留白和一点品牌色，不靠大面积渐变、玻璃、发光与动画营造高级感。

本轮实施范围应以 `desktop/src` 为主。Rust Agent、会话存储、模型协议和插件执行机制不是美化重构对象。只有确需新增的只读界面信息，才单独评估最小的 Desktop Host 补充。

### 2.2 数据从哪里来，谁说了算

```text
共享 Rust Core / Desktop Host
  ├─ bootstrap、会话快照、历史分页：已保存的真实会话
  ├─ Channel 流式批次：任务进行中的即时呈现
  └─ plugin_ui 事件与 presentation：插件提供的界面内容
                 ↓ api.ts
App.svelte：当前工作区、会话、运行状态、导航代次
  ├─ SessionSidebar / Topbar
  ├─ ChatTranscript → TranscriptTurn / LiveTimeline
  ├─ ComposerPanel → AskBar / ContextMeter
  └─ 插件组件、独立网页区域、设置与浮层
```

消息持久化仍由 Rust 管，前端只负责显示与交互。即时事件不替代真实历史；界面遗漏事件时应沿用已有快照恢复路径，不靠重新执行任务补齐。

还有两项已经存在、不能在改布局时弄丢的设计：

1. 对话面板切到设置或插件页时保持挂载，用 `hidden` 隐藏，因此输入、附件与已加载历史能够保留。
2. 快速连续点击会话已有“最后一次选择生效”与操作代次保护，不能让较晚返回的旧请求覆盖新会话。

### 2.3 当前问题：区分已确认与待实测

| 观察 | 代码依据 | 判断 |
| --- | --- | --- |
| 用户提问像引用或日志，不像一个明确的对话动作 | `.prompt` 使用左侧竖线，与正文引用的视觉接近 | 确认存在；优先改消息层级 |
| 视觉变量没有贯彻到底 | 侧栏、正文、标题、代码块、状态等仍各自使用不少固定颜色 | 确认存在；不是新增一套变量就算完成，必须替换实际使用点 |
| 宽窗口的侧栏收起状态未落到隐藏规则 | `sidebarVisible` 在 App 中切换，但 `.app-shell:not(.sidebar-visible) .sidebar` 仅位于 880px 以下的媒体规则中 | 代码可确认缺少宽窗口隐藏规则；本轮未运行原生窗口点击验证 |
| 调整窗口宽度会重设侧栏选择 | App 的 resize 处理跨越 880px 时直接设置 `sidebarVisible`，插件默认开合又只应用一次 | 确认存在；需要理顺默认值、窄窗布局与用户手动选择 |

| 跳到最新消息的位置假定输入区高度不变 | `.scroll-latest` 使用固定 `bottom: 118px` | 确认存在；附件、提问、队列和插件区域增高时需实测 |
| 样式中留有旧结构的选择器 | 紧凑模式仍有 `.message.user .user-bubble`，当前轮次已使用 `.prompt` | 确认存在；按真实 DOM 清理，不恢复已删除的 MessageView |
| 已有键盘与无鼠标场景处理，但未覆盖完整闭环 | 存在 `aria`、部分初始焦点、Escape、无悬停样式和减少动画规则；没有完整界面自动化测试 | 不能把静态检查通过等同于焦点、触屏和弹窗交互全部正确 |

## 三、先决定信息该不该常驻，再决定怎么画

| 信息或能力 | 默认呈现 | 展开后保留的能力 |
| --- | --- | --- |
| 当前工作区与会话 | 侧栏明确当前项，标题简洁 | 完整路径、搜索、多选、历史会话和跨项目导航 |
| 模型与思考强度 | 一个模型入口；非默认强度可作弱提示 | 快速选模型、改当前强度、添加模型、进入配置 |
| 上下文与用量 | 小而清楚的可点击入口，正常占用不强调 | 占用构成、容量未知说明、输入输出、缓存、工具技能、手动压缩 |
| 思考与工具过程 | 工作时显示真实进展；完成后合成一条过程摘要 | 原有思考、中间回复、工具参数、结果、失败与顺序 |
| 文件改动 | 回答附近显示简短的真实改动摘要 | 本轮改动与整个工作区改动分别查看，不混为一谈 |
| 任务队列 | 只有存在队列时才显示数量与运行/暂停状态 | 展开、重排、删除、暂停、恢复、清空 |
| 插件提问 | 正在等待回答时明确占据输入区域 | 单选、多选、自由回答、关闭；关闭不是批准 |
| 连接错误、任务失败 | 可见且有文字说明，不只用颜色 | 查看具体原因、保留输入、由用户决定是否重试 |
| MCP 配置与会话能力 | 统一设置内逐项默认开关；会话逐项开启/关闭/跟随默认 | 每个工具、Skill、MCP 服务、插件独立控制；全开/全关仅批量选中当前清单；无审批、不卸载或删配置，运行中不实际更换能力 |
| 插件界面 | 用户启用的区域与入口按原契约出现 | 自由界面、交互、任务、输入框操作和返回对话 |

不新增预算、审批层级、任务次数限制、必须先选模式等强制流程。既有执行边界不在美化中悄悄改变，也不靠禁用更多按钮营造“简单”。

## 四、统一视觉语言：有温度的石墨工作台

首版取值已按用户反馈与真实页面校准；当前方向如下，详细颜色角色以 [视觉与交互基线](desktop-visual-system.md) 和源码为准。这不是整套产品的无障碍合规结论，也不是让用户新增一页主题配置。

### 4.1 颜色、排版与尺寸

| 项目 | 当前方向 |
| --- | --- |
| 主背景 | 石墨灰 `#19191E`，避免大片纯黑，并与 Tauri 启动底色同步 |
| 侧栏背景 | 由主区派生，略暗；靠轻微层差和细边线区分 |
| 输入与浮层 | 使用独立字段、面板和浮层表面变量；阴影表达层级，不给每行都造卡片 |
| 主文字 / 次文字 | `#EEEDF2` / `#AAA7B4`；说明和占位文字同样要可读 |
| 交互强调 | 小面积灰紫 `#B8ACE8`；焦点、选中、细下划线和开关。品牌与默认主操作用中性色，不再使用青绿 |
| 错误 / 提醒 / 成功 | 独立语义色加文字或图标，不能只靠红黄绿区别 |
| 阅读宽度 | 当前默认 744px，输入与正文对齐；插件可按原契约覆盖 |
| 正文 | 默认约 15px、行高约 1.85；紧凑模式保留，不把所有文字一律放大 |
| 侧栏 / 说明 | 侧栏约 13px；主要可操作说明不缩成一片 10px 小字 |
| 字体 | 现有系统字体栈优先；中文按系统回落，不增加网络字体请求或为效果引入字体包 |
| 间距 | 以 4px 为基础，主要使用 8 / 12 / 16 / 24 / 32；删除没有必要的零散尺寸 |
| 圆角 | 轻控件约 8px，消息和浮层约 12px，输入框约 16px；不全部做成胶囊 |
| 点击区域 | 常用图标约 32–36px；窗口控制保留独立区域；触控时适当放大，不能只画小图标 |
| 动效 | 约 120–180ms 的颜色或透明度过渡；不为每个字、每条消息添加入场动画 |

品牌辨识优先来自一枚克制的 Kroma 符号、统一间距和输入框形态；不在本轮开展整套 Logo 重设计。正常文字对比度目标不低于 4.5:1，控件边界和焦点等必要视觉信息目标不低于 3:1，实施时逐项测量。

### 4.2 变量必须与插件主题打通

保留现有插件使用的 `--surface`、`--line`、`--text`、`--muted`、`--plugin-accent` 及对应颜色映射，不让新默认主题压过插件的显式设置。

实施规则：

- 从现有变量整理出背景、正文、次文字、强调、边框、状态等最小集合，不做运行时设计系统。
- 侧栏、正文、标题、代码、选中态与输入框都消费同一组语义变量；不能一边宣称支持主题，一边继续写死核心文字颜色。
- 增加少量确有使用者的内部变量可以，但不随意扩张公开插件协议。
- 正式启动背景与 Tauri `backgroundColor` 同步，避免先闪旧底色。
- 插件自带独立网页不强行注入核心 CSS；宿主统一外框，网页内部风格仍由插件控制。
- 验证默认主题、插件覆盖和禁用插件后的恢复三条路径；既有主题契约不被本轮缩减。

### 5.2 侧栏：找得到，但不抢眼

**修改文件：** `SessionSidebar.svelte`、`chat-ui.ts`、相关样式与测试。

- 保留工作区分组，不把个人对话和项目会话混成一个失去上下文的“最近列表”。
- 默认以当前工作区为主要展开项；是否保留个人对话展开由明确的初始规则决定，用户手动展开/收起后不被重新抢回。
- 当前项用柔和底色识别，去掉粗重的竖向强调；标题优先，日期弱化，不占据过多标题空间。
- 新建和搜索保留直接入口；底部只保留设置，插件并入设置分类，扩展自带的工作页仍可单独显示。
- 保留同名目录的路径消歧、当前旧会话可见、查看更多、内容搜索片段与搜索范围说明。
- 多选、删除、分组新建平时安静，悬停、键盘聚焦和无悬停设备上都能找到。
- 宽窗口和窄窗口都真正支持收起；保留顶部恢复入口。侧栏隐藏使用状态和样式控制，不为折叠销毁整个组件。
- 将“默认开合”“窄窗抽屉形式”“用户手动选择”分开处理；跨断点不无条件覆盖用户选择。只增加必要的界面状态，不引入全局偏好框架。

### 5.3 顶部：会话标题、模型、系统窗口控制

**修改文件：** `Topbar.svelte`、`ModelPicker.svelte`、`ThinkingPicker.svelte`。

- 将现有模型与思考强度的展示整合到一个选择面板，减少两个并列菜单及图标带来的碎片感。
- 模型搜索、已连接标识、添加、管理与当前临时思考强度都保留；不能把改强度变成必须进入设置的多步操作。
- 改当前强度继续走现有 `commands.changeReasoning`，不悄悄改写保存的默认配置。
- 重命名与导出作为标题附近的轻操作；键盘可达，不要求用户只能悬停发现。
- 保留 52px 左右的稳定标题栏高度；长标题、长模型名先合理截断，不能挤没关闭按钮。
- 交互区不可拖动，空白处可拖动；最小化、最大化/还原、关闭、窗口标题变化都必须在原生端验证。

### 5.4 对话：轻量消息块 + 自然展开的回答

**修改文件：** `TranscriptTurn.svelte`、`ChatTranscript.svelte`、`Markdown.svelte`、内容样式。

- 用户消息改为靠右的轻底色块，不使用对话尾巴；短消息自然收窄，长任务最多约占阅读列 85%，长路径和链接可换行。
- AI 内容继续直接排在阅读区，不增加头像墙、角色标签条或层层卡片。
- 正文段落保持紧凑，用户提问与回答、不同轮次之间明确留白；标题不能和普通正文只差一点字重。
- 过程摘要及真实改动放在回答下方，属于当前轮次的普通文档流；失败计数始终能看见，不被折叠成一个看似成功的状态。
- 没有最终回答、只有过程或错误时，保留可读的过程，不能只剩一条空摘要。
- 编辑、回退、分叉继续对应原始提问及消息索引，不因新消息壳层而错位。
- 复制只复制原有回答正文；附件、引用来源、链接、安全清理与代码块的横向滚动全部保留。
- “回到最新”锚定到对话可视区域，不再依赖输入区永远高 118px 的假设。

### 5.5 工作中：过程透明，不刷屏

**修改文件：** `LiveTimeline.svelte`、`ToolDetail.svelte`、相关轮次样式。

- 一条轻量状态先回答“正在做什么”，详细过程继续展开查看。
- 工具仍按真实发生顺序和稳定 ID 呈现；参数、输出、失败、截断说明等不能丢失或伪装。
- 流式内容直接显示，不加假打字延迟；保留现有批次合并和 Markdown 的 50/100/180ms 分级刷新。
- 用户在底部时跟随，翻阅上文后不抢滚动位置；加载更早历史时仍停留在原来阅读的内容附近。
- 完成、失败、取消、等待用户回答明确区分。取消只表示停止后续执行，不宣称已撤销此前操作。

### 5.6 输入框：主界面最精致，也最可靠的部分

**修改文件：** `ComposerPanel.svelte`、`ContextMeter.svelte`、`AskBar.svelte`；可拆出队列展示组件。

- 空闲时更低、更轻，输入多行后自然增高；仍有最大可视高度和内部滚动，不把正文完全顶走。
- 附件左、发送或停止右；占位文字建议“想做什么？”。聚焦靠清晰边框而不是大面积光晕。
- 保留现有组合键：空闲时 Enter 发送，运行时 Enter 插入当前任务，Shift+Enter 换行，运行时 Ctrl+Enter 排队。文件建议打开时，Enter/Tab 优先插入候选，不能直接发送任务；中文输入法确认候选词时绝不能误发送。美化不顺带重定义这些操作。
- 运行时仍能输入；“插话”和“后续任务”含义不同，不能合并成一个会改变执行顺序的发送按钮。
- 上下文入口缩小视觉重量，但始终可点击、可聚焦；高占用提醒沿用现有含义，不改变压缩时机或擅自自动压缩。
- 容量未知显示“未知/—”，估算值继续标明估算，不画成真实精确测量。
- 队列仅在有内容时出现，默认是一条可展开摘要；暂停不能装成正在执行，恢复操作保留明确文字。
- 插件提问继续与输入框共用一个区域。关闭提问后恢复原输入与焦点，关闭不是同意。
- 附件、提问、队列、上下文详情和输入增高要组合验收，不能只设计一个没有任何状态的空输入框。

### 5.7 提示与 MCP：不设审批，保留配置与错误说明

**最新用户决定：** Kroma 不做 MCP 审核权限限制；每个 MCP 服务独立开关，启用的服务直接按现有项目/用户配置加载，不再保留待批准提示或信任列表。

- 普通短提示用低干扰样式；失败与阻断性错误有清楚文字和恢复入口，不自动一闪而过。
- 删除后的撤销不能因为自动消失的提示而变得不可操作。
- 每个 MCP 服务的全局默认与会话开启/关闭/跟随默认移入统一能力设置；不把单项开关或批量操作变成另一种审批，关闭不删除服务定义。
- 服务清单仅显示名称、传输方式、来源，不展示环境变量、请求头或密钥值。
- 配置中的本地命令可以直接启动程序；不隐藏这个事实，也不擅自加批准步骤。

### 5.8 设置、插件页与浮层：同一个产品，不是后台拼接

**修改文件：** `SettingsView.svelte`、`PluginsView.svelte`、现有各 Dialog、`WorkspaceChanges.svelte`、`TurnChanges.svelte`。

- 统一设置提供模型、工具、MCP、Skills、插件五个分类；分类不作为能力总开关。每个工具、Skill、MCP 服务、插件都有全局默认开关，当前会话另有逐项开启/关闭/跟随默认；全开/全关只批量选中当前清单，不能取代单项。关闭不卸载或删除配置，运行中不实际更换能力。MCP 与 Skills 定义继续从现有文件读取，不新增定义编辑器。模型必要字段优先，高级参数继续折叠，不增加空分类。
- 保留 API Key 留空不改、显式清除、仅保存、保存并连接、设为默认的区别；错误后保留输入。
- 插件管理保留安装、启停、配置、详情和自定义界面入口，不把强大能力删成一个漂亮但只能开关的列表。
- 共享标题、表单行、按钮、空状态、边框和留白规则；不是给每个页面换一种卡片风格。
- 文件差异继续以易读和可操作为先，不为了“无边框”取消增加/删除、文件选择与滚动边界。
- 统一弹窗初始焦点、Tab 范围、Escape、关闭后焦点返回；有运行中操作的弹窗按其真实状态处理，不能关闭后留下看不见的任务。
- 如果多个浮层确有同一段焦点处理，抽一个小的可复用行为即可；不建通用弹窗管理器或新的浮层框架。

## 六、窗口尺寸、插件区域与可访问性

### 6.1 按真实可用空间布局

现有原生窗口默认约 1280×850，最小 780×560；窄窗规则从 880px 开始。这些是本轮必须覆盖的范围，不先扩大产品支持边界。

- 宽窗侧栏是固定导航，窄窗变抽屉；顶部始终能恢复，遮罩和 Escape 只关闭当前抽屉。
- 阅读列和输入框共用宽度变量与左右留白。打开右侧插件区后，按**聊天列剩余空间**重新布局，不能只看整个窗口宽度。
- 右侧插件区不够放时改为有明确恢复入口的抽屉；插件仍运行，不静默禁用，也不让正文被挤到不可读。
- `above_composer` 插件区域、队列和提问不能无限分走聊天高度。使用可滚动的可见区域与明确展开方式，不截断实际内容，不改插件声明语义。
- 全页不要出现无意的横向滚动；长代码、表格、差异在自己的区域滚动。
- 最小高度下仍能看见并操作输入、发送/停止、提问提交和当前错误。额外覆盖系统缩放与应用文字放大。

### 6.2 键盘、中文输入与减少动画

- 保留 Ctrl/Cmd+K、N、B、O、逗号等现有快捷键，以及插件声明的快捷键；弹窗打开时不能在背后切换会话。
- 所有仅悬停显示的操作，在键盘聚焦和无悬停设备上同样可发现。补齐当前 `.prompt-actions`、`.answer-actions` 等真实类名，不能只维护旧选择器。
- 焦点始终可见；输入区不能用 `outline: none` 后又没有等效的聚焦提示。
- 附件删除、菜单、图标按钮有可理解的名称。失败与进度不只靠颜色，不逐 Token 向辅助技术播报整页内容。
- 保留 `prefers-reduced-motion`；无必要的循环装饰动画不新增。

## 七、代码怎么整理：最少必要变化

### 7.1 继续沿用当前职责，而不是另建架构

| 层 | 继续放什么 | 不放什么 |
| --- | --- | --- |
| `App.svelte` | 页面组合、当前会话与任务状态、已有导航和操作保护 | 每种控件的视觉细节；第二份全局消息存储 |
| `components/*` | 组件局部展开状态、输入呈现、菜单与浮层、视图事件 | 模型请求、持久化会话副本、重复实现任务生命周期 |
| `lib/session-commands.ts` / `turn-actions.ts` | 现有命令与回退等操作路径 | 为每个按钮新增同义包装层 |
| `lib/*` 纯函数 | 事件折叠、轮次、草稿、队列、导航与格式化 | 与组件争夺同一份界面状态 |
| `lib/plugin-ui.ts` | 现有插件呈现和布局契约 | 为单个插件增加特殊分支 |
| Desktop Host | 原有命令、真实会话、窗口与必要的原生能力 | 为样式调整建立新服务或第二个 Agent |

具体整理顺序：

1. 从 `app.css` 提取一个小的 `tokens.css`，保留 `app.css` 管全局基础、壳层与确需跨组件的规则；不是先把 714 行拆成十几个文件。
2. 改造某个组件时才移动它的局部样式，避免一口气改全部选择器。Markdown 动态 HTML 的样式保留明确全局作用域或正确使用 `:global`，不能被 Svelte 局部作用域误伤。
3. 现有命令模块已经承担状态操作，不新增同义 controller、service、事件总线或依赖注入层。
4. 队列展示可从 Composer 拆为 `FollowupQueue.svelte`，仅接收数据和回调；队列作用域、持久化和执行仍用原逻辑。
5. MCP 配置清单与开关复用统一能力设置，不再拆审批提示组件。
6. `App.svelte` 内的运行状态本轮不全面迁出。除非实际修改证明一个职责已经独立且可测试，否则不为降低行数搬出大量互相回调的状态。
7. 清理无引用的样式与重复变量；保留现有功能测试，不恢复已经删除的 `MessageView.svelte`。

### 7.2 插件兼容是约束，不是后补项

必须保留：

- 主题覆盖及 `composer_max_rows`。
- 阅读宽度、默认侧栏开合、regular/compact 密度。
- 声明式组件的 `header`、`transcript`、`above_composer`、`below_composer`、`footer`、`sidebar` 位置。
- 独立网页的 `sidebar`、`tab`、`above_composer`、`panel`、`workspace` 区域。
- `workspace` 接管后的“回到对话”，无论插件页面是否正常都能退出。
- 插件发送状态、通知、提问、写入输入框、触发任务和收发消息的现有桥接。
- 会话切换、插件禁用、界面卸载时的状态与监听清理。
- 独立网页的 sandbox、消息来源校验、路径边界以及 Tauri 权限边界；美化不能改成直接把插件 HTML 注入主页面。

“极简”是核心默认呈现，不是要求所有插件只能画同一种 UI。协议可参考[当前插件契约](plugin-contract-v1.md)，但有分歧时以当前源码与测试为准。

## 八、必须守住的行为底线

1. 会话和项目切换前保存草稿；文本、附件与队列不能串到其他会话。文字草稿沿用本地持久化，附件沿用运行中的会话内存缓存；不把附件路径擅自持久化为重启后可自动重发的内容。
2. 设置/插件页与对话切换不销毁对话；任务可以继续，返回时内容完整。
3. 旧请求和旧任务的迟到结果不能覆盖新选择，导航与任务代次保护保留。
4. 队列与插话不同；失败和取消暂停后续队列；重开应用不自动执行保存的队列。
5. 模糊的发送失败不自动重试工具或任务，不覆盖用户在运行中继续输入的内容。
6. 停止不等于回滚；编辑、分叉、回退与文件恢复仍按各自真实语义执行。
7. 已完成快照与流式临时内容不能重复显示，也不能漏掉只有工具输出的轮次。
8. 历史分页与有界渲染继续有效；不为了动画一次挂载完整长会话。
9. Markdown 继续先清理后展示；模型链接不能替换应用页面，仅允许原有明确的外部打开路径。
10. 上下文未知、估算、实际使用与输出预留不混淆；UI 不擅自改变模型或压缩策略。
11. 插件提问的忽略/关闭不是许可；插件接管界面不能困住用户。
12. 不改 WAL、模型配置格式、应用标识和已有用户数据目录，不要求用户重新配置模型或重新导入历史。

## 九、分批落地，不做一次性大翻修

| 批次 | 做什么 | 主要涉及 | 这一批完成的标准 |
| --- | --- | --- | --- |
| 0：基线与取景 | 记录当前工作树、现有检查和代表场景；使用去敏或合成数据保存对比图 | 测试与调查文档 | 分清原有改动和本轮改动；不拿用户真实对话当公开测试素材 |
| 1：第一屏气质 | 统一变量、壳层、侧栏、顶部、空白会话；修正宽窗折叠 | CSS、Sidebar、Topbar、选择器、启动底色 | 同样的窗口尺寸下，能看到明显而一致的视觉变化；窗口按钮和导航仍可用 |
| 2：核心对话体验 | 用户消息、正文、过程位置、输入框、上下文、最新消息按钮 | Transcript、Composer、ContextMeter、Markdown | 短问答、长任务、长代码、附件和运行中状态都成立，不只是空白页漂亮 |
| 3：工作与扩展状态 | 队列、提问、错误/MCP、插件各位置、窄窗插件区 | App 的展示部分、AskBar、Plugin 组件 | 等待、失败、取消、排队、插件接管及恢复都清楚且不改变执行行为 |
| 4：统一其余页面 | 模型设置、插件管理、所有浮层、文件差异、键盘焦点 | Settings、Plugins、Dialogs、Changes | 从主界面进入任何页面都像同一个产品；密钥、输入和恢复语义不变 |
| 5：清理与回归 | 移除旧规则、补界面测试、记录性能与原生验收 | CSS、测试、Desktop 文档与相关 CI | 通过下述验收矩阵，明确尚未验证的平台或场景 |

批次 1 做出首个可运行版本就可以比较视觉方向，不等所有页面都写完才看效果。优先用真实组件和测试数据校准，不另建一个和产品逐渐脱节的展示站。

每批独立交付、独立验证；不同时升级框架、改插件协议或重写任务状态。回退以该批的最小改动为单位，不重置或覆盖调查前已经存在的用户改动；不为过渡长期保留两套主题和两套页面。

### 10.4 性能：保住已有收益，先测再优化

- 复用已有历史窗口和按需加载，不默认引入复杂虚拟列表。
- 在同一台机器、同一组内容、相同窗口尺寸下比较改造前后，覆盖 1000 条消息、高频流式文本与大工具输出。
- 记录输入响应、滚动、持续渲染耗时、空闲 CPU 与整个 WebView 进程组内存；不能把 Vite 构建耗时当成 UI 性能。
- 避免为每条历史消息注册窗口监听、轮询或动画；不把所有折叠内容永久挂成昂贵 DOM。
- 不承诺尚未实测的 FPS、启动 P95 或内存下降百分比。发现退步先定位新增变化，再决定是否需要额外机制。

## 十一、明确不做

- 不迁移 React、Electron、路由框架、全局状态库、整套组件库或 CSS 框架。
- 不全面迁移 Svelte 语法，也不因文件行数目标拆出一堆转发组件。
- 不新增核心 Agent、后台服务、第二份消息库或前端自己的恢复协议。
- 不削减插件 UI 自由、不改变已有命令协议，也不把沙盒网页改成直接访问主页面。
- 不改模型调用协议、工具执行协议、任务预算与重试；按用户最新决定取消 MCP 审批，新增主动能力开关。
- 不做完整主题商店、自由拖拽工作台、全新快捷指令系统和动效引擎。
- 不默认新增模型调用、网络请求或后台索引来支撑外观。
- 不在这轮方案任务中安装、发布、打包分发或重置用户数据。

## 十二、完成标准与剩余不确定性

实施完成至少应满足：

- [ ] 同一尺寸下，主界面、工作中状态、设置与插件页有一致且可解释的视觉层级。
- [ ] 侧栏宽窄窗口折叠、正文过程位置、最新消息按钮和输入区组合状态不再互相牵制。
- [ ] 错误、取消、待回答、队列暂停与能力设置都清楚可找，未削减控制权。
- [ ] 原有草稿、附件、导航、历史、回退和插件契约没有退步。
- [ ] 前端检查、单测、构建与新增界面测试通过；相关原生改动有对应验证。
- [ ] 有去敏的前后对比与代表状态截图，而不只有一个漂亮的空白首页。
- [ ] 清理失效样式与重复规则，不留下长期两套实现。
- [ ] 记录实际测过的平台、窗口和性能场景，明确未测项，不用一次构建成功替代 GUI 验收。

仍需通过实施样例和实际设备确定的事项：品牌色最终观感、各系统字体回落、macOS/Linux 自绘标题栏体验、长会话真实滚动性能、独立插件网页在小窗口下的表现。以上不是本轮已经验证通过的事实，也不妨碍先完成主界面第一批改造。

**建议从“视觉变量 + 侧栏/顶部 + 宽窗收起修正”开工，紧接着完成消息与输入框。先让日常对话真正好看、好用，再统一其余页面；不先造一套重型架构。**
