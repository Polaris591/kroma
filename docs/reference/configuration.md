# Configuration reference

## Profile file

`~/.kroma/config.json`, or the path in `KROMA_CONFIG_FILE`. It contains named
profiles and one active profile:

```json
{
  "active": "default",
  "profiles": {
    "default": {
      "base_url": "https://api.deepseek.com/v1",
      "model": "deepseek-chat",
      "api_key_env": "DEEPSEEK_API_KEY",
      "api_protocol": "chat",
      "reasoning_effort": "auto"
    }
  }
}
```

Fields:

| Field | Meaning |
| --- | --- |
| `base_url` | HTTP(S) API root, no query or fragment |
| `model` | Exact model ID sent to the provider |
| `api_key` | Stored secret (optional) |
| `api_key_env` | Environment variable holding the key; used if no stored key |
| `api_protocol` | `chat`, `responses` or `anthropic` |
| `reasoning_effort` | `auto`, `off`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max` |
| `deepseek_thinking` | `off`, `enabled`, `high`, `max` for compatible endpoints only |
| `context_window` | Model context capacity in tokens |
| `max_output_tokens` | Requested completion maximum |
| `thinking_levels` | Optional allowed reasoning levels |
| `catalog_model` | Explicit `provider/model` alias for a proxy or renamed model |
| `native_web_search` | `true` sends the endpoint-run Responses/Anthropic search tool; off unless set |
| `anthropic_cache_ttl` | `5m` (default) or `1h` for the Anthropic automatic cache breakpoint |
| `anthropic_stable_breakpoint` | `true` pins one cache breakpoint on the stable system prefix |
| `responses_prompt_cache_key` | Explicit Responses `prompt_cache_key`; never generated by Kroma |

### Provider cache controls

These keys are opt-in refinements, not requirements, and the defaults are
exactly what Kroma sent before they existed: Anthropic's automatic ephemeral
breakpoint, no explicit key, and server-side search off. Nothing is inferred
from a model name, a gateway vendor or a URL.

- `anthropic_cache_ttl` accepts only `5m` or `1h`; anything else is rejected
  when the profile loads. A one-hour write is charged differently, so it is a
  deliberate choice rather than a default. The checkpoint request reuses the
  same value, because a different TTL would not share the cached prefix.
- `anthropic_stable_breakpoint` adds one explicit breakpoint on the composed
  system prompt (or the last tool definition when there is no system text).
  Without it the automatic breakpoint travels with the growing tail.
- `responses_prompt_cache_key` is sent only for the Responses protocol and only
  when you set it (1-64 printable ASCII characters, no spaces). A key does not
  guarantee a hit, and some models ignore it, so Kroma never invents one.

When an endpoint rejects `tool_choice: none` on a checkpoint, Kroma stops
sending the native search definition in checkpoint requests for that client and
logs the fallback. That keeps a summary free of paid searches at the cost of a
cold tool prefix for those checkpoints; the limitation is reported instead of
being hidden.

`native_web_search` note: while the endpoint's own search tool is active, the
local `web_search` plugin definition is suppressed in the coding request and in
its checkpoint, so both send the same tool prefix.

Key precedence: `KROMA_API_KEY` → stored `api_key` → `api_key_env` environment
variable. Never put a key in a shell command or conversation.

| `KROMA_NO_MCP` | Skip MCP discovery and calls |
| `KROMA_MCP_EAGER` | Register every MCP tool eagerly (old behavior) |
| `KROMA_MCP_SERVERS` | Comma-separated MCP server allowlist |
| `KROMA_MCP_CONFIG` | Alternate MCP JSON file (treated as user config) |
| `KROMA_MCP_STDERR` | Set to `inherit` to show server logs |
| `KROMA_PLUGIN_DIR` | User plugin directory |
| `KROMA_PLUGIN_TRY` | Load one plugin directory for this run |
| `KROMA_PROFILE` | Set to `1` for task profiling output |
| `KROMA_SHELL` | Windows only: force the shell by executable name — `bash` (must be an existing file), `powershell`/`pwsh`, or `cmd`; unset auto-detects Git Bash, then PowerShell, then `cmd` |
| `KROMA_SHELL_TIMEOUT_SECS` | Optional per-command wall-clock limit in seconds; unset or `0` means no artificial timeout, and an unparsable value is logged and ignored |
| `KROMA_TOOL_IDLE_SECS` | Seconds a running tool call may produce no output before the host stops it; default `300`, `0` disables the guard |
| `KROMA_CACHE_TRACE` | Set to `1` to append per-request cache diagnostics to `<session>.cache-trace.jsonl`; off by default, and it never records prompts, tool arguments or credentials |
| `KROMA_PLUGIN_ISOLATE_ENV` | Set to `1` (or `true`) so plugin processes do not inherit credential-shaped variables; off by default, so plugins see the host environment |
| `KROMA_PLUGIN_TOOL_TIMEOUT_SECS` | Whole-call deadline in seconds for plugin tools; unset or `0` means unlimited, a smaller `[[tools]] timeout_secs` still wins, and hooks plus other non-tool calls keep their fixed 120-second timeout |
| `KROMA_NO_SUBAGENT_DELIVERY` | Any value stops the TUI from starting the delivery turn that hands finished subagent answers back to the model; an unset value allows at most two such turns between user messages, and the answers stay in their evidence directories |
| `KROMA_PROFILE_FRAMES` | Any value logs TUI draws over 16 ms and event-loop gaps over 250 ms to the runtime log |
| `KROMA_SNAPSHOT_DIR` | Test-only: output directory for the ignored `redesign_snapshot_matrix` golden-image test; the runtime never reads it |
| `KROMA_TUI_STYLE` | Removed and ignored: A / Plain is the only TUI style, so the variable has no effect |

## MCP configuration

User file: `~/.kroma/mcp.json`. Project file: `<project>/.kroma/mcp.json`.
Both load directly; project entries override user entries with the same name.
`KROMA_MCP_CONFIG` selects an alternate file instead of both defaults. No trust
store or approval environment variable is consulted. The legacy
`kroma trust-project [--revoke]` command is a no-op. Files are limited to 1 MiB;
oversized project configs produce a warning, and malformed JSON or invalid field
types produce an error. Example:

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "."],
      "cwd": "."
    },
    "remote": {
      "url": "https://example.com/mcp",
      "headers": { "Authorization": "Bearer ${TOKEN}" }
    }
  }
}
```

Relative `cwd` values are resolved against the project root; absolute working
directories and paths outside that root are allowed. Server
processes start only when `mcp_search` or `mcp_call` needs them. A single `mcp_search`
has a 30-second total budget across servers; slow or unavailable servers are
reported in the result instead of blocking discovery indefinitely. Idle lazy
servers are closed after five minutes and reconnect on the next use.

## Sessions and checkpoints

Sessions live under `~/.kroma/sessions/`. `--print` and `--json` create a fresh one
unless `--continue` or `--session` is used. File snapshots live under
`~/.kroma/checkpoints/` and are separate from the project `.git`. Snapshot history is
bounded per session (older batches are pruned once it exceeds 200 commits).
Delete that private store to reclaim its space.
