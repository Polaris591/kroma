# Kroma Graphite：TUI 视觉与交互改版计划

状态：设计规划，尚未实施。本文不表示实现代码、测试或真实终端验收已经完成。

## 1. 设计决策

采用一个方向，不并列多套皮肤供后续拼接：**石墨手稿的视觉 + 输入台与折叠记录的交互**。

- 安静：大部分界面是中性色，蓝粉只标识身份、焦点与活动。
- 精确：正文、过程、状态有明确层级；工具结束不等于任务目标完成。
- 连贯：首页、对话、选择器共享版心、文字起点和输入台。
- 有辨识度：原版三楔形 Logo、粉色输入标记、蓝色回复标记、就地展开的输入台。
- 保持终端属性：不依赖字体大小、阴影、透明模糊、图片协议或复杂动画。

首版不做侧栏、默认双栏、卡片墙、持续贯穿全文的树形线、自动回滚或新的 UI runtime。

## 3. 配色规格

### 3.1 默认 dark 色板

| 令牌 | 色值 | 用途 |
| --- | --- | --- |
| background | `#101114` | 全局石墨背景 |
| surface | `#17191E` | 输入区、代码块、少量局部内容 |
| overlay | `#20232A` | 选择器与临时检视 |
| text | `#E5E3DF` | 柔和纸白正文 |
| muted | `#A8ACB6` | 工具摘要、次级说明 |
| faint | `#858D9B` | 时间、快捷键、辅助信息 |
| border | `#303640` | 装饰性细分隔，不承担唯一的焦点提示 |
| accent / accent_text | `#9AAEFF` | Kroma、选中项、焦点 |
| user | `#D5A1AD` | 用户消息起始标记、输入提示符 |
| success | `#8FC5A4` | 确认成功的状态 |
| warning | `#D9B879` | 警告、阈值、结果未知 |
| error | `#E69393` | 错误和失败 |
| tool / code | 分别复用 muted / text | 保持旧键与渲染接口兼容 |

颜色分工：

- 蓝、粉不铺大面积背景；正文不整段着品牌色。
- 成功工具摘要文字使用 muted，成功符号小面积使用 success。
- 不为每条普通回复增加绿色完成行。
- 只有执行过程、代码与检视需要局部表面，不为用户和助手各画消息框。
- 原版 Logo 保留原三色；品牌图形与正文色板不强行统一。
- 所有渲染色从 Theme 获取，保留自定义主题、插件配色和活动帧覆盖能力。

### 3.2 对比度与其他主题

已经用相对亮度公式计算上述 8 个文字/状态色在 background、surface、overlay 上的 24 组对比度，均不低于 4.5:1；最小值为 faint 在 overlay 上约 4.70:1。

相比上一轮讨论，将 faint 从 `#818997` 调整到 `#858D9B`，给浮层文字留出对比度余量。此计算不是终端实测；混合后的选中背景、Diff 底色与语法高亮组合仍须单独测试。

- light 同步采用相同的层级和颜色语义，不套用 dark 的具体色值；实施时计算并确定浅色令牌。
- mono 使用终端原生前景/背景，靠标记、粗细和间距区分；不把颜色作为唯一的信息渠道。
- 原有 `theme.toml` 可继续解析；沿用 dark/light/mono，不增加重复的新预设。
- 低对比 border 只用于装饰；当前选中项另有可见标记与文字强调。

## 4. 排版规格

所有尺寸使用终端显示列与行，不使用像素；中文、组合字符与附件按显示宽度计算。

### 4.1 版心与对齐

- comfortable：终端宽度至少 116 列时，工作区固定为 112 列并居中；较窄时左右各留 1 列，具体尺寸以避免溢出为前提。
- wide：保留现有 `/layout wide` 的全宽用途，不将宽屏用户强制锁回 112 列。
- comfortable 的正文可用宽度最多 96 列；代码、表格、Diff 可用满工作区内部宽度。
- 页眉与分隔线对齐工作区；消息正文与输入文字共享工作区内约 4 列的正文起点。
- 不同内容采用不同最大行长，但共享左侧基准，不分别居中。

### 4.2 垂直节奏

- 常规高度：页眉 1 行，加 1 行间隔；页脚 1 行。
- 输入区：单行草稿占 3 行，保持上下内边距；多行随内容增长，保留既有高度上限与插件约束。
- 历史导航提示只在阅读旧记录时占 1 行。
- 同一轮内的工具记录紧凑排列，正文段落适度留白；两轮之间留出更清楚的间隔。
- 40×16 使用紧凑页眉与短文案，优先保留可读历史和可编辑输入，不为 Logo 挤占内容。
- 保留零尺寸和极小终端保护，不因改版增加越界访问。

### 4.3 文字层级

- 正文：text、普通字重；用户消息不再默认整段加粗。
- 重要标题或短强调：有限使用 Bold，不将整屏变成亮白粗体。
- 工具摘要：muted；运行中和失败的关键内容提升为 text。
- 时间与提示：faint；关键失败信息不能弱化成辅助灰。
- 不依赖斜体才能识别状态，避免终端字体差异造成语义丢失。

## 5. 各区域设计

### 5.1 页眉与页脚

页眉只负责会话身份与项目上下文：左侧 Kroma / 会话标题，右侧项目与分支。空闲时不反复显示 Ready；活动的主要指示留在当前工作记录末尾。

- 失败、中断状态在记录中明确保留，不因移除重复状态而丢失。
- 页脚默认只放模型、思考强度、上下文及放得下的帮助入口。
- Cache、完整 token 数与详细用量移入现有 `/usage`；插件状态仍有可访问的查看路径。
- 80 列必须看得到模型、思考强度、上下文；更窄时依次紧凑、截短，不能用隐藏模型换取辅助信息。
- 未知显示 `—`，估算保留 `~`；不伪造零值。保留上下文 70%/90% 的警告/错误语义。

### 5.2 首页

首页是开始工作的区域，不是品牌海报。

- 小尺寸原版 Logo + Kroma 字标；不再堆叠宽字距字标和长快捷键说明。
- 起始区域靠近输入台，上方自然留白；最近会话标题与正文基准对齐。
- 最近最多 3 个会话，标题主、时间次；短终端依次减少会话数和品牌图形。
- 最近会话可点击，键盘通过既有会话选择器访问，不劫持普通数字键。
- 最近项必须携带实际 session ID，通过现有恢复流程打开，不能以标题代替身份。
- 路径只出现一次，模型只在页脚出现；启动不自动恢复会话，不创建空会话记录。
- Logo 与欢迎区共享布局结果，避免两处分别估算位置造成重叠。

### 5.3 对话记录

- 用户：去掉整行 surface，保留粉色短标记；多行正文按普通字重排版。
- Kroma：首行一个蓝色品牌标记，正文纸白；后续每段不重复角色标签。
- 不绘制持续贯穿全文的树状线；轮次结构通过起点标记、间距与导航反馈表达。
- 代码块保留轻表面、高亮与复制动作；装饰和标签不进入复制文本。
- 普通问答完成后安静结束；含工具活动的轮次保留可展开执行记录。
- 耗时只显示真实已有的数据；当前仅有最新任务统计的字段，不足以生成所有历史轮次耗时。恢复会话后未知就不显示，禁止填入 0 秒或虚构统计。
- Git 变化仅称工作区观察结果，不声称一定由 Agent 造成。

### 5.4 输入台与选择器

输入区使用轻表面、顶部细线、粉色提示符；去掉整圈圆角框。保持现有编辑区内边距，单独验证 IME 光标位置。

命令、模型、会话、文件候选都在输入台上方展开，使用同一组边距、选中标记、说明列和焦点提示。不另开一个与输入区脱节的居中小窗。

保留两种不同的确认语义：

- `/` 补全：上下键选择，Tab 或 Enter 只插入命令，之后 Enter 才执行。
- Ctrl+P：沿用既有选择与执行规则；文件选择插入草稿，会话恢复和模型切换仍受空闲限制。

草稿与查询规则：

- Ctrl+P 查询不能覆盖原有草稿；取消后恢复文本、光标和附件。
- 斜杠补全编辑的是用户正在输入的命令草稿，Esc 关闭候选但保留所输入的文本。
- 窗口缩放、取消、选择、切换类别后，都要重新计算焦点、光标和命中区域。
- 首版不扩大运行中可执行命令的范围；Enter 引导与 `/queue` 仍沿用现有任务边界。

### 5.5 执行记录与后续检视

首版保留现有相邻工具分组，改善视觉，不重新定义语义分组：

- 成功组默认一行，展开看步骤；单步展开看完整命令/输出。
- 运行中只保留必要的实时尾部预览。
- 失败、诊断警告、中断和结果未知默认可见，不得折叠成成功摘要。
- 不仅凭 exit 0 宣称测试全部通过，也不从命令名称猜测文件已修改。

后续增加输入台上方的有界只读检视区，用于长命令与输出：

- 复用现有面板的滚动、文本与焦点能力，不建立第二套日志数据源。
- 显式打开，Esc 返回原阅读位置和草稿；第一版不做编辑区与检视区双焦点并行输入。
- 提供点击入口与空闲时 Ctrl+P 的“检视执行记录”入口，保证键盘可达。
- Ctrl+T 继续表示全文记录和搜索；Ctrl+O 继续提供原位详情展开。
- 检视区关闭后不留下固定面板，不变成默认双栏。

## 6. 必须保持的行为

- 保持现有 Ctrl+C 的层级规则：选区复制、普通工作视图取消/清草稿/退出、模态层自身的关闭规则，不因视觉改版改写。
- Esc 不取消 Agent、不清普通草稿；仅关闭对应候选、路径输入或检视层。
- Shift+Tab 切换思考强度；选择器内的 Tab/Shift+Tab 切换类别仍由选择器拥有焦点时处理。
- Alt+↑/↓ 轮次跳转，Ctrl+End 返回最新；流式输出不抢走已固定的阅读位置。
- 保持鼠标选区、拖动滚动条、Ctrl+点击链接、原始代码复制和附件操作。
- 保持 Unicode 字素簇编辑、撤销/重做、长文本粘贴与 Windows IME。
- 保持双语；新增文案走既有 Language，不改变模型回答与工具原始输出。
- 保持插件标签、颜色、活动帧和受约束的布局覆盖，不将默认视觉硬编码成不可覆盖。
- 不新增依赖，不改 Prompt、模型请求数、工具 schema、压缩策略或 session/WAL 格式。

## 8. 验收标准

### 自动化

实施后各批次运行适用的格式、lint 和 TUI 回归；最终运行全量回归：

```sh
cargo fmt --all -- --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked --offline tui::
cargo test --locked
```

- 快照矩阵继续覆盖 dark/light/mono × 40×16、80×24、100×30、160×40 × 现有 20 个场景；新增入口与检视状态补充测试。
- 不只断言字符：检查表面/文字颜色、对比度、选中态与实际命中区域。
- 修改旧断言时逐个说明视觉决策变化，保留可读性、错误可见性与复制纯净等原始意图。
- 对新增影响缓存的展开状态、焦点与宽度变化做失效测试，避免点击后不更新或每帧全量重排。
- 运行现有 80×24、300/3000 条记录流式性能基准，与同环境改版前数据比较；目标绘制 p95 ≤ 40ms，同时调查相对基线的明显退化。
- 不在 draw 中增加进程、模型请求、阻塞 IO 或不可控扫描。

### 真实终端

至少在 Windows Terminal 检查：

1. 中文输入与候选窗：首页、普通输入、运行中、弹层关闭、多次缩放后位置正确。
2. 中英文多行、Emoji、附件、长粘贴、撤销重做与草稿恢复。
3. 工具失败/中断未被成功完成提示掩盖；未知结果没有绿色成功含义。
4. 选择器不越界、不盖住正在编辑的输入；关闭后焦点回到正确位置。
5. 阅读旧记录时，流式新增不跳动；返回最新与轮次跳转有效。
6. 鼠标选择、链接、代码复制、工具展开、最近会话点击没有命中区域错位。
7. light/mono 可读；不支持某些字形的环境有文字与普通符号的可理解表达。

最终交付必须包括真实终端截图或录屏对照。文字快照通过不等于视觉和输入手感通过。
