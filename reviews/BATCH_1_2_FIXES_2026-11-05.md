## 第一批：正确性与安全边界

- 文件快照：同一私有 store 的初始化、快照、列举、恢复和裁剪使用 OS 事务锁；恢复旧快照会删除后来才被快照收录的文件；支持空树与文件/目录切换，保留忽略文件、排除目录和用户 Git 元数据。
- 取消快照：任务取消可中断锁等待和 Git 子进程树；清理私有临时文件与遗留 Git 锁；下一次事务可继续执行。快照失败通过 Warning 事件展示，任务计时包含 snapshot_ms。
- 恢复边界：不沿符号链接或 Windows junction 祖先删除/写入外部文件；阻塞路径可在恢复报告中检查。Git 命令使用私有 Git 目录、索引和隔离配置。
- 插件授权：扫描全部 authored local regular files，而非猜测脚本扩展名；覆盖 Python、无扩展名、自定义数据文件和超过 1 MiB 的 JS helper。扫描有条目数、总字节数和单文件上限，扫描不完整时拒绝项目授权。
- 插件生命周期：禁用插件发现只读元数据；启用时重新扫描；损坏或无法验证的插件仍可禁用。内容改回原样时不因 mtime 变化而要求重启。
- 工具结果：after hook 失败不会把已成功执行的工具标记为失败；撤回失败 hook 的局部改写，保留真实结果与实际参数。警告独立持久化后再通知 Host；恢复会话不会重放已完成副作用。
- Host 一致性：未知自定义模型清除旧报告；支持显式报告随 model/budget 一起替换；Host tools/prompt 成为 idle reload 基线，插件 overlay 不重复叠加。同步处理模型显示名称。
- Desktop：补齐 ProviderProfile.api_key_env；普通保存保留环境变量引用，显式清除或新 inline key 会清除旧引用。
- npm：cwd 测试使用 realpath，避免 macOS /var 与 /private/var 的路径别名误报。

## 第二批：冗余工作清理

- 上下文准备复用同一次保守 token 估算和未改变边界的 source-byte 统计，不更改阈值或投影规则。
- Shell 直接依据结构化退出状态判定成功/失败，不再序列化后重新解析 JSON 判定。
- TUI 与 Desktop 共用文件附件导入、大小限制、类型识别和私有存储实现。
- 会话目录、MCP 授权、插件状态和快照事务共用最小 OS sidecar 锁实现；不在持锁时删除锁文件。
- CLI 共用纯全局参数解析，并在主入口一次性应用环境覆盖；保留旧 RunOptions 和 parse 接口，移除重复扫描和无效调用。

## 验证限制与兼容提示

1. 本机为 Windows x86_64-pc-windows-gnu。普通 Desktop cargo test --lib 编译成功后，测试 EXE 因缺少 Common Controls v6 manifest 在装载 TaskDialogIndirect 时退出（STATUS_ENTRYPOINT_NOT_FOUND）。为验证实际测试逻辑，使用 cargo rustc 的 test profile，仅对库测试显式链接 Tauri 已生成的 libresource.a，再运行生成的测试 EXE；6 项通过。没有把导致资源重复的临时 build.rs 改动留在代码中。

本机成功执行的编译方式：

    cargo rustc --locked --manifest-path desktop/src-tauri/Cargo.toml --lib --profile test -- -C link-arg=D:/Kroma/kroma-latest/desktop/src-tauri/target/debug/build/kroma-desktop-dc7a413620eb79a0/out/libresource.a

随后运行本次生成的 desktop/src-tauri/target/debug/deps/kroma_desktop_lib-0b0545cc90cfeb5d.exe。OUT_DIR 与 EXE hash 是构建产物，重新构建时应以实际输出为准。普通 GNU 测试执行器的 manifest 配置仍是构建环境限制，不宣称标准命令已经无条件通过。

2. 未在 macOS/Linux 实机执行；macOS cwd 规范化修复已在 Windows 测试中验证其可移植调用方式，但不能替代 macOS CI。
