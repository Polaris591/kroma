# A / Plain — 语义色设计稿

状态：已选用 **S2「清晰状态」**，并接入 A / Plain 默认渲染器。本目录的 `index.html` 保留三种用色强度的设计对比；实际运行采用 S2，安装状态以部署版本为准。

目标：保留 A 的黑白灰主体，用少量高辨识度颜色表达明确语义，不给品牌、正文或编辑区大面积上色。

打开 `index.html`，可以比较三种用色强度、深浅背景以及执行、完成、失败、代码差异场景。

## 语义前景色

| Token | 名称 | 近黑背景 | 银白背景 | 语义 |
|---|---|---|---|---|
| status.running | 明亮蓝 | `#7AA2F7` | `#245BB4` | 正在连接、思考、生成或执行 |
| status.success | 明亮绿 | `#86D99A` | `#2C6B3C` | 明确确认的成功，不代表整轮任务都成功 |
| status.warning | 琥珀 | `#E5B567` | `#80550E` | 需要注意，或结果仍未知 |
| status.error | 珊瑚红 | `#F07886` | `#AA3547` | 明确失败、错误或阻断 |

| diff.remove | 珊瑚红 | `#F07886` | `#AA3547` | 差异中的删除，不表示执行失败 |

角色身份色与状态色分开：用户竖线 `#A78BFA`（银白 `#6D4AC7`），Kroma 竖线 `#5ED3D3`（银白 `#0F6B6B`）。角色标签使用同一身份色；两套颜色与消息灰底均保持至少 4.5:1，且不与运行蓝、成功绿复用。

状态前景色已计算主背景、消息灰底、代码表面和浮层上的对比度。最小值：深色约 6.14:1，浅色约 4.58:1，均不低于 4.5:1。分隔线不是正文，不采用同样的文本对比度要求。

## 三种用色强度

### S1 — 克制点色（对比方案）

- 小范围状态符号着色；命令、诊断正文和普通说明仍为灰白。
- 上下文风险只给读数用色，不染整条信息栏；模型、思考等级和缓存不变色。
- 代码差异只给 `+` / `−` 标记用色，不铺红绿底。
- 成功与忙碌有反馈，但不抢走正文层级。

### S2 — 清晰状态（已选用）

- 状态符号与短状态词一起着色；成功工具记录只保留符号，运行 / 失败 / 警告 / 未知才附短状态词，避免每条成功都重复 `Done`。
- 不给整行命令、长日志、AI 回答或输入区域上色。
- 其他规则与 S1 一致，适合更强调快速扫读的用户。

### S3 — 异常优先

- 成功和运行中的状态仍为灰色。
- 警告与失败的符号用色。
- 链接悬停、上下文风险及 diff 增删继续使用专门语义色。

## 使用规则

- 正文、模型名、思考等级、输入提示符、光标和边框维持中性灰白；`YOU / KROMA` 角色标签使用各自的身份色。
- 消息身份竖线使用独立紫罗兰 / 青绿角色色；用户和 Kroma 消息共用中性灰底，灰底右侧与滚动条之间留 3 栏终端底色接缝，作为可见的安全边距。已有助手内容时，青绿竖线连续穿过正文、思考、工具记录与状态行；用户消息后的连接状态则另起独立状态行，与用户块之间留一行终端底色分隔。这些身份色不表达执行结果，不复用成功 / 失败判定。
- 「思考 high」是配置，不是正在思考，不因此染蓝。
- 上下文低于 70% 为灰，70–89% 为警告，90% 及以上为错误。分母是模型总窗口，不是累计会话用量。
- 缓存命中率是测量，不当作成功率。缓存低、0% 或未报告都不自动画成错误。
- 未知值 `—` 为灰，不伪造零，也不因缺少测量就显示警告。
- 主动取消通常是中性状态；中断且执行结果或副作用未知，才使用警告。
- 恢复后仍未知的工具结果不能画成成功。失败后重试时，保留旧失败记录，当前运行单独标识。
- 成功不能只依据命令名称或模型描述推断；颜色使用已有结构化执行状态，不新增颜色驱动的状态判断。
- 链接默认灰色下划线，仅有效链接悬停时显明亮蓝。
- diff 增删与执行结果是不同语义：删一行代码不等于失败，增加一行代码不等于成功。
- 正常日志中的 `+` / `−` 不自动当成 diff。
- 所有状态仍保留符号和文字，不只依赖颜色。

## 实现与验证

`src/tui/semantic.rs` 将语义前景色与基础灰阶分开。没有把全局 `accent` 改成蓝色，因此输入提示符、普通代码关键字和编辑器强调仍为中性。`src/tui/messages.rs` 负责消息灰底、紫 / 青身份色，以及把同一回合的正文、思考、工具和完成状态纳入一条连续竖线；两者都独立于 S2 的成功 / 失败语义。

工具和任务前缀呈现语义符号；运行、失败、警告和未知状态再附短状态词。成功记录不重复 `Done`，亚秒耗时也隐藏；命令、时长和诊断正文保持灰白。`/diff` 使用明确的显示类别，不把普通命令输出中的 `+` / `−` 自动当成差异。差异变换只调整前景色，保留源文本、制表符展开规则与代码复制元数据。

`cargo test --locked --lib tui::view::semantic_tests` 验证色值、对比度、工具状态、上下文阈值、链接悬停、diff 无损性、通知作用范围、原生单色与编辑区隔离。

`cargo test --locked --lib export_plain_preview -- --ignored --nocapture` 可导出实际 Ratatui 场景至 `reviews/tui-plain-runtime/index.html`，不调用模型。

上述对比度为真彩 RGB 的计算结果。`mono` 模式不强制注入 RGB，保留原生前景、符号和文字；256 色终端的近似映射需要在接入阶段另做实机验证。

没有增加新的 Agent、模型请求、工具重跑或会话迁移。语义色只表达现有状态，不参与业务结果判断。
