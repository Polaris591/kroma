# Round 7 — 可读 Shell 结果：复杂 Rust 留出任务对照

日期：2026-11-10。状态：**完成 2 轮交叉尝试；无证据批准默认启用**。

## 目的

在先前小任务的 JSON→可读文本实验之外，用一个此前未参与消融的真实 Rust 模块修复任务，判断保留完整信息的可读 Shell 输出是否减少模型决策回合且不损害正确性。

- 模型：`deepseek-v4.1-flash`，High，现有 Cobblemon Chat Completions 配置。
- 两组**同一个实验二进制**，仅切换 `KROMA_EXPERIMENT_READABLE_SHELL_RESULTS=1`；默认关闭。
- 仓库从同一个 `git archive HEAD` 生成独立拷贝。注入历史搜索 Unicode 大小写折叠/字节偏移回归，冻结回归测试。
- 任务要求修复后自行执行 `cargo test --locked --offline --lib excerpts_`。验收再运行现有 excerpt 测试和注入且冻结的回归测试；回归测试在项目中可见，因此不能称为真正隐藏测试。
- 两轮预定执行顺序：第一轮 JSON→Readable；第二轮 Readable→JSON。
- Kroma 主分支、系统 Prompt、压缩策略均未修改。

第一轮可读文本比 JSON **多 24.172 秒（约 21.4%）**，输入 Token 多约 **81.3%**，但工具调用少一次。不能用工具调用次数单独认定效率更高。

第二轮两组虽通过独立代码测试，但**都没有在时间限制内完成用户要求的正常任务收尾**；按事先定义的严格验收均不通过。可读组一轮较长的模型请求耗时约 68 秒，不能把所有超时归因于重复检查。

## 实验设施中断

第二轮最初一条远程测试调用被连接层中断，`rust_history_unicode/2/json/project` 已创建但该运行未形成完整日志；随后复用目录会导致 `FileExistsError`。该条是**实验驱动设施错误**，不是模型失败。JSON 对照因此在全新恢复实验目录单独重跑，且同样达到 210s 截尾。两组结果文件均保留，设施异常条目不能混入成功率统计。

## 实现和验证

- `src/agent.rs` 新增实验级请求投影，将确认属于 Shell 的结构化结果以标签和原文本呈现。
- 仅在模型请求拷贝中转换，保留 WAL 的原始 JSON、`tool_call_id`、工具失败标记；Shell 结果不满足格式条件、插件等非 Shell 工具保持原样。
- 实验开关默认为关闭，不暴露为正式产品设置。
- 此前的 Rust 单元测试：778 通过、0 失败、11 按设计忽略；`cargo fmt --all -- --check` 与 Clippy 通过。实验驱动自身 `--self-test` 通过。
- 实验 Prompt 改动已经撤回，主分支不受影响。

## 决策

**暂不合并默认可读输出。** 这是一个支持“改善可读性未必减少复杂 Rust 任务模型回合”的反例；但两轮中只有第一轮正常完成配对，样本和截尾不足以断言哪一种表示更优。保留默认关闭的研究开关和可重跑夹具，避免重复先前的小任务消融。当前证据不支持再通过堆叠 Prompt 或修改一次性压缩算法来补救。
